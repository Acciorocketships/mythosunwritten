# Spirit orb iteration

The merged code already moved spirit lights and sprites together. It used a 2.2m quad, 0.6m horizontal amplitudes and a relatively quick 0.65-radian/second vertical bob. The chosen candidate uses a 3.2m soft quad, wider core, 1.5m sideways amplitudes with 0.12/0.09-radian/second frequencies, and a 0.4m bob at 0.25 radians/second. Pulse frequency is reduced to 0.45 radians/second. The light count and range are unchanged in this issue.

The size/motion regression failed before on size and excursion, then passed with the 16 existing biome FX/field tests: 17 tests, 1,190 assertions, exit 0. The first replay nevertheless showed no visible sprite. Diagnostic material and shader renders isolated the fragment output: the unshaded additive shader had black ALBEDO and put its radiance in EMISSION. Outputting the radiance through ALBEDO makes the actual production sprite visible. A nearby static yellow particle had initially disguised that failure. Diagnostic images are retained and are not accepted game art.

The replay uses real generated geometry and 11 existing orb positions saved during issue 2, fixture SHA-256 32ac7509b5e679b75bb09ecf88a1778db35dd1e4b0ac174fdbd10a76125724be. Runtime scripts were stripped from that snapshot, so its captured sprite positions serve as identical replay anchors. Only orb adapters are rebuilt from production code. This isolates the current orb behavior; it does not revalidate historical fixture water or buildings. The first close orb initially appeared to be obscured by old fixture water; the diagnostic shader isolates the actual cause as its fragment output. Both close views show the sprite after correction, including its motion at all four times. The original approach camera remains a distance view.

The frozen fixture emits three pre-existing absolute AnimationPlayer path errors while instantiating and resource/RID teardown warnings. These are recorded; its render geometry loads and both comparisons exit 0. Targeted production tests have no such errors.
