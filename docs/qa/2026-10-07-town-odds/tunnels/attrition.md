# Tunnel attrition (tunnel chance 1.0)

Generated by `tests/harness/tunnel_attrition.gd`; counters are diagnostics only (fingerprint unchanged: FINGERPRINT_MATCH).

## Counters in plain words

- `walk_cells`: interior cells of every street walk the carver visited (first and last cell of a walk are skipped).
- `eligible`: cells where the massif could carry a bore (`_tunnel_bore` returned a bore). Cells skipped by the run cap are not tested and not counted here.
- `rolled_out`: a run start refused by the seeded roll (0 at chance 1.0).
- `daylight_gap`: a run start refused because the previous run had no daylight cell after it.
- `run_capped`: cells where a run already had 3 bored cells, so no bore was tried.
- `bored_cells`: unique tunnel cells after carving. Unit mismatch with `eligible`: `eligible` counts walk-cell visits (one per visit, per walk), while `bored_cells` counts unique tunnel cells, which also include the second lane's cell of two-lane bores (`_tunnel_bore` `width`), gate covers and authored `wall_tunnel` lanes added before the loop, and cells shared by two walks count once. That is why bored (109) can exceed eligible (98). The size of each effect is unquantified (no `bore_width_cells` counter was added).
- `pruned_cells`: tunnel cells removed later when destination pruning dropped optional lanes.
- `final_tunnel_cells`: tunnel cells left when plots are laid.
- `tunnel_covers`: records returned by `cover_tunnels` (one per tunnel cell, success or not).
- `covered`: records with no refusal reason, i.e. a house storey really was placed over the crown.
- `released_crown_cells`: stone cells later released as unborne crowns (`maze_released_unborne_crown_cells`, whole-town).

## Largest loss

Ranking note: this ranking starts from the 107 bored cells. In raw count the carve stage (694 walk cells -> 98 eligible) is the bigger drop, but it is a drop of walk cells, not of tunnels, and includes open-sky streets the massif never covers.

Of the 107 tunnel cells that survive carving and pruning, only 16 (15%) end up with a house storey over them: `cover_tunnels` (`WarrenPlotPlanner.gd:1141`) refuses 91. Refusal reasons are first-failure ordered (the checks run in sequence and the first failing one is recorded), so later reasons, notably the jamb check (29), are lower bounds. In order: the crown column already carries another plot (30, `:1161`), passage walls do not bear on two jambs (29, `:1165`), no adjacent house storey over the crown (20, `:1169`), no crown stone (5), would overtop the citadel plinth (4), edge-ring or support-rule rejections (3). This is the largest loss among tunnel cells.

Upstream, only 98 of 694 walk cells (14%) can be bored. The seeded roll (`TUNNEL_START_CHANCE` 1.0), the daylight rule (`MIN_DAYLIGHT_RUN`) and the run cap (`MAX_TUNNEL_RUN` 3) cost almost nothing (0, 0 and 4 cells); the losses are the physical tests in `_tunnel_bore` (`WarrenMazeCarver.gd:1887`), above all the massif needing `top_at >= roof + 2` over the bore width and solid jamb columns (`:1924` onward). `_tunnel_bore` has no per-reason counter, so that split is not measured. Destination pruning removes only 2 cells.

`released_crown_cells` is a town-wide count of unborne crown stone released (`maze_released_unborne_crown_cells`), not tunnel-specific; it is shown for context only and says nothing about stone over tunnels. The final stage, whether a given tunnel's crown survives the later release, is not measured per tunnel.

Caveats: 12 towns; `walk_cells` includes open-sky street cells, so 14% understates the boreable share. `covered` is cells with a PLOT_OVER, not whole tunnels.
