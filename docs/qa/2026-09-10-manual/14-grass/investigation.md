# Grass loading latency — investigation

Baseline begins after the accepted terrain-streaming corrections. The graphical harness uses the actual world/character, the production grass runtime and default terrain radii. It records 250 ms grass readiness samples, queue lifecycle events, worker computation, upload timing, three biome arrivals and 40-second physical walks. Each destination receives matched stationary captures at terrain release and 2/10/30 seconds later, plus two nearby views. Forest and heath use the source photo-11/photo-19 reconstructed cameras; the meadow is an additional unpictured review site.

## Alternatives and red-first checks

Increasing grass radius can increase queue work without addressing starvation. A separate worker would need genuinely independent terrain/water ownership; the existing mutable canonical caches cannot simply be read concurrently. Reducing density would change the reviewed carpet rather than its arrival time.

The first candidate instead corrects scheduling. Visible full-density grass currently ranks after all future terrain and its road/water dependencies. Also, the worker can start another long job before the main thread integrates the previous result and queues newly eligible grass. Three focused failing tests pin these ordering/handoff behaviors (`grass-red-tests.txt`, 3/6 assertions).

Visible grass now precedes future terrain, while current terrain and feature/collision dependencies remain first. Distant grass retains its existing background tier; approach rebases a queued tile. Chunk completion waits for the normal main-thread commit/request handoff before another dispatch. This is a scheduling handoff, not a grass gate on movement. Undrained results remain owned, and shutdown still wakes the worker normally. Nine queue tests pass 29 assertions (`grass-green-tests.txt`).

The running graphical baseline still uses the pre-change scripts loaded at launch. Those exact files are retained under `/private/tmp/september10-grass-before-code`. Timing and visible acceptance remain pending. No grass assets, density, field placement, collision or shader have changed.


The baseline completes three visits. Forest grass is ready at release and the 41.37 m walk has no delay. Heath arrival becomes ready within 0.66 s, but its 178.21 m physical walk has 15.689 s of unprepared underfoot tiles and 20.288 s of missing nearby tiles, with zero terrain freezing. At least 3.571 s occurs on tiles later observed to contain real grass. Upload maxima remain below 0.5 ms; average tile computation is 26–58 ms. This identifies queue delay independently of empty riverbed populations.

Visual inspection finds the extra unpictured meadow fixture's old y=4 datum below the current ground. Its 0.699 m attempted walk is invalid, not an obstacle traversal result. The already-running first candidate uses the same old fixture; neither meadow walk will be credited. Future unpictured sites now resolve the actual collision floor before capturing or walking. The independent far route will provide a grounded 80-second graphical traversal and fixed-world cameras along the walked corridor. Source photo pins retain their recorded positions.


Candidate 1 is rejected before startup completes: after one grass job finishes, 40 jobs remain queued and the worker sleeps. The new chunk handoff had consumed queued wake tokens, but visual completion assumed another token still existed. The focused wake regression fails 1/10 assertions before correction. Visual completion now posts the next dispatch when work remains, independently of prior token history. The stopped run's final observation is retained in `candidate1-rejected.json`; it is not successful performance evidence.


The full grass/queue/cancellation suite passes 30 tests / 116 assertions after the wake correction. Candidate 2 is running with priority and handoff corrections only. A further baseline trace shows background road owner `(3,-13)` active for 34.223 s while grass is queued directly beneath the moving character. Those requests were not present when the background job started. The new preemption regression fails 1/12 assertions before correction: existing atomic PathPlan cancellation boundaries now yield noncritical planning when visible grass arrives. Current-ground/startup/arrival feature dependencies cannot yield. Completed nodes/routes remain cached, and the existing main-thread cancellation handoff republishes the unfinished request. Water and mesh stages do not discard completed terrain for grass preemption. This newest correction is reserved for candidate 3; candidate 2 does not contain it.


Candidate 2 is rejected: the heath repeats 59 unprepared-underfoot samples and 78 missing-near samples during its 176.36 m walk. The unpictured meadow then exposes a fixture read-only constant assignment; the copied fixture dictionary corrects that, and no meadow evidence from this run is credited. The unrun cooperative-preemption prototype is archived, not used in production.

Candidate 3 instead prepares all 64 ordinary CPU grass tiles with the parent terrain's existing region, water and feature context. Ground publication owns these resource-free packed buffers; eviction releases them. The existing 60/84/108 m GPU ring and budget remain unchanged. This removes secondary grass worker jobs and their scheduler/handoff/preemption machinery. The dataflow regression fails 0/3 assertions before and passes afterward while a long road job is already active. Extra CPU work before ground publication and retained buffer bytes must be measured; this is not accepted merely because queue tests pass.


The grounded 80-second baseline traverses 792.15 m with zero terrain freezing but 4.873 s of unprepared grass underfoot and 11.589 s of missing nearby tiles. Every missing underfoot tile is later confirmed nonempty. The readiness trace independently reproduces pop-in away from the photographed heath. The initial interpretation of the time-20 bare strip is corrected below. Baseline startup is 169.320 s and distant arrival 187.066 s.

Initial ownership implementation passes 20 queue/cancellation tests / 62 assertions, then 10 grass field/commit/lifetime tests / 68 assertions. Full 64-tile ownership is verified in positive and negative chunks; selected child packed buffers, AABBs and counts exactly match ordinary individual field computation. A weak-reference test confirms the ground owner releases the population on eviction. Final travel and visual checks remain pending.


Candidate 3 completes the forest and heath visits. Forest travels 41.370 m and heath 176.335 m, both with zero frozen time. All 157 heath walking samples have both underfoot and nearby grass prepared, compared with 15.689 s of unprepared underfoot and 20.288 s missing nearby in the baseline. Settled populations are exactly 11,204 forest and 3,920 heath instances in both runs. Heath arrival increases from 168.302 to 219.620 s. This added cold preparation cost is material and is reported separately from successful walking. The corrected meadow fixture and independent 80-second candidate route remain outstanding.


The three-site candidate is complete: corrected meadow travels 257.501 m with zero missing grass and zero frozen time. The full pure field/streamer/trample/queue suite passes 43 tests / 450 assertions; the updated committed-parent integration check adds 1 test / 3 assertions. Twelve forest/heath camera records match exactly. Six corrected meadow candidate views are visually inspected, but their invalid older baseline is excluded from paired claims.

Preparation cost (`preparation-cost.json`): the baseline computes 184 requested tiles in 10.673 worker seconds. Candidate 3 prepares 48 complete chunk populations in 164.368 worker seconds, maximum 6.731 s/chunk. These are different work scopes, not a per-tile speedup. The candidate holds at most 18.445 MB of prepared instance buffers in this run, with 1,088 prepared tiles at peak; this buffer lifetime follows terrain eviction. Total static peak is 2,608 MB versus 2,688 MB in the baseline, but differing traversal/queue progress prevents crediting this as a memory reduction. The independent long-route candidate is now running.


Candidate 3 long-route completes 792.149591 m with zero grass delays and zero terrain freezes. Its startup is 185.000 s and arrival 210.649 s (the interim commentary estimate of ~202 s was premature). Packed grass buffers peak at 21.556 MB. Nevertheless, matched time-60 images reveal later distant terrain/dressing, so candidate 3 is rejected. Its production source is archived as `candidate3-streamer.gd.txt` and `candidate3-field.gd.txt`. A dedicated grass worker will require detached sampling inputs: `HeightfieldRegion.plan` must be removed, grade caches privately cloned, water fill/shore data separated from mutable plans and lazy dry-ground caches, and feature sampling limited to immutable ground fields. Merely sharing the canonical terrain/water caches would be unsafe.


Candidate 4 uses `GrassSamplingContext` and `GrassWorkQueue`. The terrain worker publishes detached region/grade/water sampling data with each chunk; the dedicated visual worker computes only the existing nearby GPU ring. It never calls the terrain/road/water planners. Grade controls and continuous-source chains have private caches; the region has no plan back-pointer. Water retains completed fill and shore arrays but no source traces, hydraulic plan or lazy dry-ground memo. Feature sampling retains only sealed immutable ground fields. The aliasing regression fails 7/8 assertions with shared references and passes all eight after detachment. A threaded test reproduces an occupied terrain planner and verifies grass completion plus exact ordinary instance buffers. Teleport cancellation and shutdown release checks pass. The first full candidate-4 run passes 44 tests / 448 assertions. Populated fine-shore coverage is added next.

The new class import initially scanned generated QA screenshots; that import was stopped after registration. `docs/qa/.gdignore` excludes those non-runtime review artifacts from Godot's importer (no runtime resource references point there). The importer could not save editor settings under the sandbox; no application settings were changed.

The long-route camera harness now also captures seconds 46/48/50/54 to photograph the measured baseline delay, rather than infer it from the unrelated time-20 bare strip. A new frozen pre-grass-fix baseline will precede candidate-4 graphical tests.


The completed-fill snapshot additionally passes 2 tests / 12 assertions, including 1,008 shoreline points with populated coarse/fine arrays, signed shore distance, and both wet/dry branches. Sampling equality is exact. Canonical ownership is omitted; the private grade source chain preserves continuous-extension values. The grass queue admits only the current visual radius, cancels abandoned queued work on teleports, and joins its one bounded tile computation at shutdown. Main-thread uploads remain under the existing budget.

The idle-worker weak-reference regression fails before the explicit local release: GDScript retains the last `job` and `sampling` locals across the semaphore wait. Clearing those references before completion publication fixes the retained detached terrain owner. The final grass/queue/trample/sampling run passes 45 tests / 452 assertions. Fixed-scene rendering diagnostics now stop the visual worker as well as terrain scheduling before measuring frames.

The additional-camera frozen baseline travels 780.993 m with zero terrain freeze. Its sampled walk has 6.706 s of unprepared underfoot grass (5.679 s independently confirmed nonempty) and 14.832 s missing nearby tiles; startup 170.307 s, distant arrival 187.847 s. Extra image captures alter actual distance slightly, so compare the new matched run rather than mixing camera schedules.
